# Assets - Your Personal Workspace

Interface update 4. Backup ledger format remains version 2.

A personal dashboard for everyday money, investments, trading results and loans.
Uses your supplied SVG logo, your exact gold tick PNG, and the palette
#0C0E09 / #202020 / #FCFF1A. The badge is decorative, not identity verification.

## New in this update

A mobile Quick Update page gives direct access to spending, income, trading P&L,
transfers, balance corrections and loan repayments. It is an extra view, not a
reduced replacement for desktop. The complete dashboard and all previous pages,
custom date pickers, logos, photos, CSV reports and JSON restore are retained.

The installable public app shell starts on Quick Update. Home-screen installation
is offered where the phone's browser supports it; iPhone instructions are also
inside the app. The public service worker caches interface assets only, never
API responses or financial records.

An optional private backend adds owner login, cross-device revision-checked sync,
server-side daily snapshots, downloadable cloud JSON and cloud restore with a
pre-restore snapshot. Backend snapshots run inside Supabase Postgres via pg_cron,
not a browser timer. No production dependency installation is needed.

## Activate cloud functionality

**Read SETUP.md.** Backend code is included, but no live database, authentication,
GitHub upload or production deployment has been performed for you. Cloud backup
is not active until you configure the database, scheduler and Vercel environment,
sign in, and explicitly upload your real workspace.

Use the complete source package for the existing GitHub/Vercel project. The
standalone HTML download is an alternative local interface, not a backend.
Do not publish financial JSON backups in your repository.

## Local data and existing files

The existing `vault.personal.assets.v1` browser storage key is preserved.
Version 1 and 2 JSON backups still import, without replaying transactions or
repayments. Your real financial backup, profile image and account logos are NOT
embedded in this public code package. Initial data is clearly marked demo data.

Cloud-backed edits save locally before syncing. Offline changes remain pending
on that device until the app is online again. A daily snapshot includes only
records already saved on the server by its cutoff, not later offline changes.
Simultaneous conflicting copies are reviewed rather than silently merged.

## Project structure

- index.html / styles.css / app.js: full public interface and all views.
- tickmark.png / logo.svg / icons/: supplied branding and rendered app icons.
- api/vault.js: Vercel API for authentication, sync and snapshots.
- lib/security.js: encrypted HttpOnly cookies, origin checks and API helpers.
- lib/validate-state.js: v2 ledger validation, shared in behavior with local app.
- database/: schema, server-side scheduler, owner authorization and checks.
- scripts/build.mjs: explicit allow-list for public deployment assets.
- manifest.webmanifest / sw.js: home-screen app metadata and public-shell caching.
- SETUP.md / .env.example / vercel.json: deployment instructions and configuration.
- tests/: generic, non-personal Node test fixtures and regression tests.
- test-report.json: what was tested, and what has not been tested.

## Build and test

```sh
npm test
npm run build
```

Tests use Node's built-in test runner; there are no npm runtime dependencies.
The public directory is generated by the build. Use Node 22.x on Vercel.

The implementation includes safeguards, but is not an independent security
audit, a banking system or a guarantee of uninterrupted backup service. Keep
independent private JSON downloads and monitor scheduler/database health.
